# Private sync v1 interoperability gate

## Status: first safe increment, not a cross-device sync release

This change adds an **unwired conformance foundation**. It does not add GitHub
networking, a document writer, persistent credentials, a merge engine, background
sync, UI changes, or a new protocol. The existing iPhone implementation and the
original `private-memory-sync-v1.json` envelope fixture are unchanged.

`Tests/Fixtures/private-memory-sync-interop-v1.json` is deliberately marked
`pending-native-export`. It contains **no invented Foundation output**. Swift,
Xcode, Gradle and the Android SDK were unavailable during local implementation.
At that point native export/comparison and Android compilation/tests were pending;
the first CI results are recorded below. Passing
portable tests while the native fixture test skips is **not** release approval.

## What is implemented

- `Tests/PrivateMemorySyncInteropTests.swift`: synthetic fixtures generated by the
  actual Swift JSONEncoder, production merge/restore functions and CryptoKit.
  The exporter attaches a JSON file to its XCTest result; it does not read user
  memory or write to a vault or repository.
- Python `companion/private_sync_codec.py`: binary64 reference-date preservation,
  strict UUID/domain spelling, conflict and restoration identities, bounded
  strict JSON parsing, exact UTF-8 import passphrases and read-only AES-GCM remote
  envelope authentication. It is not imported by the CLI or application.
- Kotlin `sync/SyncCodec.kt`: the same date/identity/passphrase primitives, with
  unit tests. It is not connected to the Activity. Android encryption/KDF and
  shared native-fixture consumption are deliberately not implemented yet.
- `python -m scripts.private_sync_interop FIXTURE.json`: an explicit, failing-closed
  native prerequisite check. It rejects the pending marker, missing coverage,
  changed date/string bytes, identity/envelope mismatch and nonconvergent native
  Unicode probes. Success verifies only the primitives, not a portable serializer.

The intended later `decode_document`, `encode_document` and `canonical_record`
interfaces are **not exposed**. Generic `json.dumps`, `JSONObject` and a new JSON
canonicalization standard cannot safely implement the current identity protocol.
The Python strict JSON helper is untyped; authenticated decrypted bytes are still
untrusted until the future full document validator succeeds. It must reject a
journal rather than accepting its shared encryption envelope as a remote vault.
No journal encryption/decryption API or deterministic encryption API is added.

## Contract the native export captures

Each record vector stores input JSON bytes and exact native canonical bytes as
base64, plus a fixed-width big-endian binary64 date bit string where applicable.
Coverage includes mixed-case UUID input with letters, escaped slash/quote/backslash
and controls, NFC/NFD strings, supplementary scalars, U+2028/U+2029 and optional
source fields that are absent, null or empty. Dates cover integer/fraction values,
negative zero, valid negative Apple seconds, positive/negative subnormals,
scientific-notation thresholds, present-day nextUp and both allowed Unix bounds.
Malformed date and duplicate-key/nesting probes record native behavior without
silently redefining it. Portable strict parsing intentionally rejects duplicate
keys, nonfinite numbers, unpaired surrogates and nesting beyond 64 levels.

Conflict vectors derive the expected ID by calling the real Swift merge. Restore
vectors call the real explicit import restoration across three generations for
notes and chats. Document vectors preserve equal-date source chat order despite
UUID lexical order. AES-GCM envelopes use native random salt/nonce and synthetic
ASCII, NFC, NFD and supplementary-character passphrases, including whitespace.
Random ciphertext is checked by decryption, never by regenerating identical bytes.

### Dates and identity

Foundation dates are binary64 seconds since 2001-01-01, offset 978307200 from Unix.
`721692800.0000001 + 978307200 - 978307200` loses the low bit. Keep the original
reference-time bits separately from a SQLite/Unix/UI projection. Preserve signed
zero until native output establishes its behavior; do not impose a new v1 rule.
Date validity follows native addition to Unix and the range 0...253402300799.

Record UUID text is Foundation uppercase; tombstones and hash-domain UUIDs are
lowercase, hyphenated canonical values. Conflict identities use SHA-256 over
UTF-8(kind + ':' + lowercase original UUID) followed directly by **exact native
canonical loser bytes**, truncated to 16 bytes with version-5 and RFC variant bits.
This is not namespace UUIDv5. Restoration hashes the NUL-delimited domain from
`PrivateMemorySyncRestore`, with version-8 bits; tombstones are never removed.
The isolated primitive tests' literal hash vectors are independent algorithm
checks, not claimed Foundation golden record encodings.

### Unicode convergence blockers

Swift String equality treats some different UTF-8 sequences as equal. The export
records both merge directions for NFC/NFD chats and equal-byte-length filenames
with canonically equivalent combining-mark order, plus an ordinary filename tie.
A differing forward/reverse payload must block new writers even if all runtimes
faithfully reproduce it. The checker compares actual bytes, not just a `converges`
flag. Do not change current iPhone behavior in this increment or bless a divergence
as a valid expected result. Resolve it with a coordinated, tested protocol plan.

### Knowledge deletion and grouping probes

The native exporter also calls the unchanged production validator/merger with:
- An accepted selected-file snapshot containing its entry ID in `suppressedIDs`,
  comparing a one-sided merge, duplicate merge and identity merge.
- The same file cached at reference seconds 100 and 200, with a third snapshot
  clearing before 150, comparing both merge groupings.

The accepted-input flag is recorded only after snapshot/document validation
succeeds. Both normalized outputs are retained as exact bytes. The gate verifies
the synthetic input cases and rejects any non-idempotence or grouping divergence.
Source inspection predicts risks here; only native execution can establish the
actual outputs. No production behavior is altered to make these probes pass.

### Chat grouping probes

The exporter also compares `M(M(A, B), C)` and `M(A, M(B, C))`, using an empty
base at every merge. The two chats have identical per-ID records and the same
reference date (100); A contains ID 0, B contains ID 1, and C explicitly orders
ID 1 before ID 0. Inputs are validated before export. The gate requires these
exact inputs, both records unchanged in each output, and equal output bytes.
A rendered total order may lose ordering provenance between merge rounds, so
pairwise symmetry alone is insufficient.

A second case uses one original chat ID with A=(X, date 100), B=(X, date 200)
and C=(Y, date 150), again comparing both groupings with an empty base. It exports
the actual canonical input records as well as documents, allowing the gate to
check derived conflict IDs without inventing Foundation bytes. The output must
retain both X and Y, contain only supplied text/date combinations, and have equal
bytes across groupings. Timestamp-only collapse can otherwise interact with
content-based conflict IDs. Both new native probes still need execution.

## Standalone seed CI

`.github/workflows/private-sync-conformance.yml` runs only for pushes to
`feature/private-sync-conformance`, with read-only repository permissions and no
saved checkout credential. It does not run on main, modify the release workflows,
package an IPA, publish an APK, update a feed or release anything.

Its three independent jobs run the full companion suite on Linux/Windows/macOS,
the full script suite on Linux/macOS and portable conformance scripts on Windows, Android
unit tests/lint/debug build, and the native exporter on macos-15/Xcode 26. The
native job deliberately selects **only** `testExportSyntheticNativeGoldenVectors`.
It does not run the pending committed-golden comparison during this seed phase.
General Python tests retain their clearly labeled pending-native skip.

The native job exports XCTest attachments even after a test failure, selects
exactly one actual native-format fixture (opaque filenames are supported), saves
its original bytes as `build/sync-conformance/native-export.json`, then runs the
non-skippable primitive/convergence gate against that file. Missing, ambiguous,
pending or invalid exports fail. A recorded convergence defect also fails while
retaining its evidence. Nothing replaces the committed fixture automatically.

Each job records exact `GITHUB_SHA`, Git tree, and actual tracked-diff summary and
name/status, index-vs-HEAD and working-tree-vs-index summaries before and after
execution; mismatched SHA or tracked changes fail, including opposing staged and
unstaged edits that would cancel in a simple HEAD-to-worktree comparison.
Only generated untracked/ignored output is excluded from the tracked-source check.
The native artifact additionally records Xcode/Python versions and the owned
simulator's exact runtime/device identity. Bounded cleanup shuts down only that
owned device. Job cancellation or runner loss can still prevent cleanup/upload;
no CI system can promise artifacts after the runner disappears.

Always-retained artifact paths:
- Every job: `build/sync-conformance/`, including provenance and logs.
- Native: `SyncInterop.xcresult`, `attachments/`, `native-export.json`, and
  `simulator/` beneath that directory.
- Android: also `android/app/build/reports/` and `android/app/build/test-results/`.
  Generated APKs are intentionally not uploaded.

A passing seed is **not release-ready**. The next reviewed phase must commit the
real native fixture, run `testCommittedNativeGoldenVectorsMatchThisRuntime` and
the full native/platform suites with no missing golden skips, and resolve every
convergence blocker before any writer work is enabled.

## Unwired knowledge-join foundation validation

`App/KnowledgeSyncJoin.swift` is an unused, pure remove-wins helper for a future
reviewed protocol. Existing app/cache/merge call sites do not call it. Its 17
native tests cover normalization, operand/grouping laws within compatible bounded
states, exact UTF-8 and binary64 ties, source/scope validation, and fail-closed
capacity limits. This is not a document-v2 implementation or a migration.

The native seed job now runs `KnowledgeSyncJoinTests` in its own bounded
`xcodebuild test` invocation before exporting unchanged legacy vectors. Evidence
is independent beneath `build/sync-conformance/`:
- `KnowledgeJoin.xcresult` and `foundation-tests.log`: actual native helper results.
- `foundation-summary.json`: raw `xcresulttool get test-results summary` output.
- `foundation-check.json`: exactly 17 passed, zero failed and zero skipped tests
  are required. Missing or malformed counts fail; a success still records
  `release_ready: false`.
- Existing `SyncInterop.xcresult`, `native-export.json` and `export-gate.log` retain
  the separate legacy results, including all seven native-proven divergences.

The legacy exporter runs after a successful owned-simulator boot even if the
foundation test or its evidence check fails. Its convergence gate remains a real
failure, not an allowed failure or expected-success substitution. Consequently,
the overall job is expected to remain red until the existing protocol is corrected;
inspect the independent foundation steps/artifacts to determine that helper's
outcome. No failing export replaces the pending golden fixture.

The job budget is 110 minutes to cover the separate bounded native invocations and leave time
for evidence retention and owned-simulator cleanup. Individual native invocations
remain bounded at 15 minutes, with per-test timeouts. The original 14-test run compiled:
13 methods passed and the combined capacity method exceeded its 120-second allowance.
After splitting the four boundary cases, run 42543836823 attempt 2 recorded 14 passed
methods and three 120-second timeouts in the source-byte cases. The 15-minute invocation
bound then interrupted result-bundle finalization; there is no valid complete knowledge
summary from that run. Its source was `8e32980a745a24b9df91bed38c55a63a7c51ff1a`.

The three byte-capacity tests now use 65,536 four-byte emoji scalars per record rather
than 262,144 ASCII scalars. Explicit assertions retain exactly 256 KiB per record and
the actual 50 MiB boundary/overflow totals. Every count, suppression, overflow and
production validation check remains intact; only the synthetic fixture's scalar density
changes. This reduces the number of scalar checks, not the byte limits or test scope.
Native completion within the unchanged allowances is still unproven and must be measured.

## Equivalent manual native export and later golden verification

Run on an isolated exact-commit checkout using the same Xcode 26 version as release
CI. Record commit, Xcode build, simulator runtime and test result with the artifact.
Use `macos-15`, Python 3.12, Xcode 26 and `xcodegen`, matching the repository's
native CI. Keep the job's token read-only (`contents: read`), with no vault or
release secrets. A proposed standalone job should use these commands in order
(`GITHUB_ENV` is provided by GitHub Actions):

```sh
set -euo pipefail
XCODE=$(find /Applications -maxdepth 1 -name 'Xcode_26*.app' | sort -V | tail -1)
test -n "$XCODE"
sudo xcode-select -s "$XCODE/Contents/Developer"
xcodebuild -version
brew install xcodegen
python3 -m pip install -r companion/requirements-sync.txt
xcodegen generate
mkdir -p build
python3 scripts/ci_simulator.py boot --output build/sync-interop-simulator --github-env "$GITHUB_ENV"
```

In the next workflow step, `SIMULATOR_ID` is populated from `GITHUB_ENV`:

```sh
set -euo pipefail
xcodebuild test -project AsterionVeyra.xcodeproj -scheme AsterionVeyra \
  -destination "platform=iOS Simulator,id=$SIMULATOR_ID" \
  -destination-timeout 120 -parallel-testing-enabled NO \
  -test-timeouts-enabled YES -default-test-execution-time-allowance 120 \
  -maximum-test-execution-time-allowance 180 \
  -only-testing:AsterionVeyraTests/PrivateMemorySyncInteropTests \
  -resultBundlePath build/SyncInterop.xcresult CODE_SIGNING_ALLOWED=NO
xcrun xcresulttool export attachments --path build/SyncInterop.xcresult \
  --output-path build/SyncInteropAttachments
```

Always retain `build/SyncInterop.xcresult`, `build/SyncInteropAttachments/`,
`build/sync-interop-simulator/` and command logs as a **synthetic-only** artifact,
including on a failing gate. Record `git rev-parse HEAD` and `xcodebuild -version`
in its provenance. Do not package or publish an IPA from this job.

Use the attachment manifest to locate the one named
`private-memory-sync-interop-v1.json`. Review that it contains synthetic inputs
only. Replace the pending fixture only after that exact export passes all coverage
and convergence gates; a divergent diagnostic export must remain separate. Retain producer/test
provenance separately; the artifact's own label is not execution evidence.

1. Run `python3 -m scripts.private_sync_interop <exact exported attachment path>`
   against that attachment. Do not use `continue-on-error`, `|| true`, or the unit
   test suite's skip status as the gate. During the later committed-golden phase,
   also run the same command against the checked-in fixture; its pending marker
   must fail. The seed workflow checks only the actual fresh export. A failure is a
   blocker to investigate, not permission to rewrite the expected bytes.
2. Rerun native `testCommittedNativeGoldenVectorsMatchThisRuntime` and the full
   native suite against the committed fixture. Its byte comparisons must pass
   with **no skipped golden test** on each supported release Xcode/runtime.
3. Implement portable canonical record encoding and full typed document validation
   in later increments, using these fixtures for byte-for-byte expectations. Check
   native -> Python/JVM and Python/JVM -> native envelopes and normalized documents.
4. Add Kotlin shared-fixture consumption and run Gradle unit tests/lint/build.
   Prove JCA PBKDF2 Unicode behavior and AES-GCM on Android API 26 and current API;
   ASCII-only success is insufficient. Never add custom cryptographic fallback.
5. Run merge/storage/transport/credential/signing/security gates from the broader
   sync plan before enabling any writer. No flag in this increment enables one.
